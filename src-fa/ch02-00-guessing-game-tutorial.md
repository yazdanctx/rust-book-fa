این چپتر یه بازی کلاسیک `guessing game` میسازیم تا یکم ترسمون از یه سری مفاهیم پایه ای `Rust` بریزه.

یه سری مفاهیم مثل`let`، `match`، متد ها، `associated functions`، `external crates` و یه سری چیزای دیگه.

اینم بگم که داخل چپتر های بعدی اینارو با جزئیات کامل باز میکنم و فعلا فقط میخوام دستمون راه بیفته.

منطق برنامه هم که خیلی ساده اس و اینجوریه که یه عدد رندوم بین ۱ تا ۱۰۰ تولید میکنه بعد از یوزر میخاد که یه عددی رو همینطوری حدس بزنه، بعد وقتی که شما عدد رو وارد کردی سه تا حالت هست:

- حدست کمتر از عدد اصلی بوده.
- حدست بیشتر از عدد اصلی بوده.
- عدد اصلی رو درست حدس زدی.

و اینجاس که برنامه با توجه به این شرط ها یک سری رفتار های متفاوتی از خودش نشون میده که الان میریم پیاده سازیش میکنیم.

## گرفتن حدس از کاربر

بخش اول برنامه باید یه `input` یا ورودی از کاربر بگیره، بعد این ورودی رو پردازش کنه و فرمتشو اینارو چک کنه و این داستانا.

بیا اصلا از همون قدم اول شروع کنیم، اون اول گفتم که ما میخوایم یوزر بیاد یه عدد رو حدس بزنه، درسته؟ خب شما کد لیستینگ ۲-۱ رو داخل `src/main.rs` بنویس.

<span class="filename">نام فایل: src/main.rs</span>

```rust
use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}
```

<span class="caption">لیستینگ ۲-۱: کدی که یه حدس از کاربر میگیره و چاپش میکنه</span>

همین چند خط کدی که میبینی کلی اتفاقات مختلف داره میفته، اول برای اینکه بتونیم ورودی رو بگیریم و خروجی چاپ کنیم، باید لایبری `io` (مخفف `input/output`) رو بیاریم توی اسکوپ. 

این `io` هم بخشی از استاندارد لایبری `Rust` هست که بهش میگیم `std`:

```rust
use std::io;
```

خود `Rust` میاد یه سری چیزارو به صورت پیش فرض از استاندارد لایبری خودش میاره داخل اسکوپ برنامه و به این مجموعه میگیم `prelude` و میتونی لیست کاملش رو توی [مستندات استاندارد لایبری](https://doc.rust-lang.org/std/prelude/index.html) ببینی.

حالا شما میخوای یه چیزی استفاده کنی که داخل `prelude` نیست، خودت باید دستی با `use` بیاریش داخل اسکوپ، نمونه اش همین `std:io` که برای گرفتن ورودی از کاربر بهش نیاز داریم.

همونطور که داخل چپتر ۱ دیدی، فانکشن `main` نقطه شروع برنامه اس:

```rust
fn main() {
```

سینتکس `fn` یعنی داریم یه فانکشن جدید تعریف میکنیم. پرانتز های خلی `()` هم یعنی این فانکشن پارامتری نمیگیره و آکولاد `{` هم که شروع بدنه فانکشنه.

بعد این `println!` یه ماکرو (`macro`) هست که یه رشته رو روی صفحه چاپ میکنه:

```rust
    println!("Guess the number!");

    println!("Please input your guess.");
```

این دو لاین کلا دارن یه تکست روی صفحه چاپ میکنن، ولی در ادامه ما نیاز داریم که کارو یکم پیچیده تر کنیم و ورودی کاربر رو ازش بگیریم و داخل یه متغیر ذخیره کنیم.

### ذخیره کردن مقادیر داخل متغیر ها

خب طبیعتا قدم بعدی اینه که یه متغیر (`variable`) بسازیم تا ورودی کاربر رو توش نگه داریم:

```rust
    let mut guess = String::new();
```

اینجاس که ماجرا جالب تر میشه! توی همین یه خط کوچولو کلی چیز داره اتفاق میفته.

یه دقیقه اینو ولش کن بذار اول بهت بگم که این `let` چیه.

شما اگه با زبان های دیگه کد زده باشی قطعا قبلا چشمت به `le‍t` خورده و داخل `Rust` هم ما با `let` میتونیم متغیر بسازیم. یه مثال ساده:

```rust
let apples = 5;
```

این لاین یه متغیر جدید به اسم `apples` میسازه و مقدار `5` رو بهش بایند (`bind`) میکنه.

توی `Rust` متغیر ها به صورت پیشفرض غیرقابل تغییر (`immutable`) هستن. یعنی همینکه یه مقدار بهشون دادی، دیگه اون مقدار عوض نمیشه. این مفهوم رو توی چپتر ۳ بخش «متغیر ها و تغییرپذیری» مفصل باز میکنم.

ولی خیلی اوقات هست که شما میخوای متغییرت قابل تغییر (`mutable`) و باشه، در این سناریو شما میای یدونه `mut` قبل اسم متغییرت میذاری:

```rust
let apples = 5; // immutable
let mut bananas = 5; // mutable
```


> نکته: سینتکس `//` یه کامنت شروع میکنه که تا آخر همون خط ادامه داره. `Rust` هرچی داخل کامنت باشه رو نادیده میگیره. کامنت هارو توی چپتر ۳ بیشتر توضیح میدیم.

حالا برگردیم به بازیمون. الان شما میدونی که `let mut guess` یه متغیر قابل تغییر به اسم `guess` میسازه.

علامت مساوی (`=`) هم به `Rust` میگه که میخوایم همین الان یه چیزی رو به این متغیر بایند کنیم. سمت راست مساوی هم همون مقداریه که `guess` بهش بایند میشه، یعنی خروجی صدا زدن `String::new`، فانکشنی که یه نمونه (`instance`) جدید از `String` برمیگردونه.

خود این [`String`](https://doc.rust-lang.org/std/string/struct.String.html) هم یه تایپ رشته‌ ایه که ‍‍`standard library` بهمون میده.

اون سینتکس `::` توی `String::new` یعنی `new` یه فانکشن وابسته (`associated function`) روی تایپ `String` هست.

فانکشن وابسته (خیلی فکر کردم، اسم بهتری براش پیدا نکردم حقیقتا) یعنی فانکشنی که روی یه تایپ پیاده‌سازی شده که اینجا میشه روی `String`. 

بعد این فانکشن `new` هم یه رشته‌ خالی جدید میسازه.

> این `Associated Function` یعنی یه تابع که مال خودِ `struct`ـه و نه مال یه `object` خاص. مثلا `String::new()` یعنی " برای این `String` یه چیز جدید بساز ". چون هنوز هیچ `String`ای نداریم، با `::` صداش می‌زنیم. پس فقط یادت باشه که `::` → تابع خود `instance`، `.` → تابع یه `object`.
> اگه برات گیج کننده هست اشکال نداره، یاد گرفتن این مباحث سخته و زمان میبره و الان باید چشمت آشنا بشه.

اصلا شما روی خیلی از تایپ ها یه فانکشن `new` میبینی چون برای یک فانکشنی که یه مقدار جدید میسازه، استفاده ازین اسم `new` یک کار رایجی هست.

پس در کل الان فهمیدیم که لاین `let mut guess = String::new();` یه متغیر قابل تغییر ساخته که فعلا به یه `String` خالی و جدید بایند شده. 

هوووف!

### گرفتن ورودی از کاربر

یادته که ما اول برنامه با `use std::io;` امکانات ورودی/خروجی رو آوردیم توی اسکوپ؟ حالا میخوام فانکشن `stdin` رو از ماژول `io` صدا بزنم و باهاش ورودی کاربر رو بگیرم:

```rust
    io::stdin()
        .read_line(&mut guess)
```

حالا اصلا اگه اول برنامه `use std::io;` رو هم نمینوشتیم، بازم میتونستیم از این فانکشن استفاده کنیم منتها باید کاملش رو مینوشتیم یعنی `std::io::stdin`. 

این فانکشن `stdin` یه نمونه از [`std::io::Stdin`](https://doc.rust-lang.org/std/io/struct.Stdin.html) رو بهت میده که در واقع یه هندل (`handle`) به ورودی استاندارد ترمینالته.

بعدش لاین `.read_line(&mut guess)` میاد متد [`read_line`](https://doc.rust-lang.org/std/io/struct.Stdin.html#method.read_line) رو روی همون هندل صدا میزنه تا ورودی کاربر رو ازش بگیره.

کار `read_line` دقیقا اینه که هرچی کاربر تایپ کرده رو برمیداره و به انتهای اون رشته اضافه میکنه (بدون اینکه محتوای قبلیش رو پاک کنه)، برای همینم خود رشته رو بهش پاس میدیم و چون قراره محتوای رشته عوض بشه، اون رشته باید حتما `mutable` باشه.

در ادامه ما `&mut guess` رو هم به عنوان آرگومان بهش پاس میدیم تا بهش بگیم ورودی کاربر رو کجا ذخیره کنه.

اون `&` هم یعنی این آرگومان یه رفرنس (`reference`) هست. حالا رفرنس چیه؟

رفرنس ها این امکان رو بهت میدن که چند جای مختلف کدت به یه دیتای واحد دسترسی داشته باشن، بدون اینکه لازم باشه اون دیتا چند بار توی مموری کپی بشه.

رفرنس ها یه فیچر پیچیده‌ ای هستن و کلی سوراخ امنیتی ایجاد میکنن و اصلا یکی از مزیت های بزرگ `Rust` هم دقیقا همینه که کار کردن با رفرنس ها رو خیلی امن و راحت میکنه.

حالا شما برای تموم کردن این اپ ساده که لازم نیست تمام جزئیات رو تا فیها خالدون بدونی و فعلا فقط اینو بدون که رفرنس ها هم مثل متغیر ها به صورت پیشفرض `immutable` هستن. 

برای همینم باید بنویسی `&mut guess` نه `&guess` تا قابل تغییر بشه. (چپتر ۴ کامل درباره رفرنس ها حرف میزنم الان فقط میخوام با کانسپت آشنا بشی.)

### مدیریت خطاهای احتمالی با `Result`

پسر رو همین یه لاین کد، اینهمه حرف زدیم تا حالا!! هووووف!!

تازه الان رسیدیم به لاین سوم:

```rust
        .expect("Failed to read line");
```

حالا ما اصلا میتونستیم همه اینارو اینجوری هم بنویسیم:

```rust
io::stdin().read_line(&mut guess).expect("Failed to read line");
```

ولی خب یه خط خیلی طولانی، سخت خونده میشه و کلا بهتره که خوردش کنی که بعدا کسی خواست کدتو بخونه دهنش سرویس نشه.

کلا شما وقتی داری متد هارو با سینتکس `.method_name()` صدا میزنی، شکستن لاین ها و اضافه کردن اسپیسینگ کمک زیادی به خوانایی کد میکنه.

 حالا ولش کن بیا ببینیم این خط چیکار میکنه.

همونطور که گفتم، `read_line` هرچی کاربر وارد کرده رو میریزه توی رشته‌ ای که بهش پاس دادیم، ولی در ضمن یه مقدار `Result` هم برمیگردونه.

این [`Result`](https://doc.rust-lang.org/std/result/enum.Result.html) یه [`enumeration`](ch06-00-enums.md) هست که بهش خلاصه میگیم `enum`. 

یعنی یه تایپ که میتونه توی یکی از چند حالت ممکن باشه. به هر کدوم از این حالت ها میگیم یه ورینت (`variant`).

توی چپتر ۶ کامل درباره `enum` ها حرف میزنیم نگران نباش، الان کانسپتو بگیر که بعدا یه ذهنیتی داشته باشی. کار این تایپ `Result` هم اینه که اطلاعات مربوط به مدیریت خطا رو داخل خودش نگه داره.

ورینت های `Result` عبارتن از `Ok` و `Err`.

ورینت `Ok` یعنی عملیات موفق بوده و مقدار تولید شده رو هم داخل خودش داره. ورینت `Err` هم یعنی عملیات شکست خورده و اطلاعاتی درباره اینکه چرا و چطور شکست خورده رو داخل خودش داره.

بعد این مقادیر تایپ `Result` هم مثل هر تایپ دیگه‌ ای، یه سری متد روی خودشون دارن. مثلا یه نمونه از `Result` متدی به اسم [`expect`](https://doc.rust-lang.org/std/result/enum.Result.html#method.expect) داره که میتونی صداش بزنی.

حالا اگه این نمونه از `Result` یه مقدار `Err` باشه، `expect` باعث میشه برنامه کرش کنه و همون پیامی که بهش پاس دادی رو نشون بده. (ببین اگه `read_line` یه `Err` برگردونه، به احتمال زیاد به خاطر یه خطا از سمت سیستم عاملته.)

ولی اگه این نمونه از `Result` یه مقدار `Ok` باشه، `expect` مقداری که داخل `Ok` نگه داشته شده رو درمیاره و همون رو بهت میده تا بتونی ازش استفاده کنی. توی این مورد خاص، اون مقدار تعداد بایت های ورودی کاربره.

شما اگه `expect` رو صدا نزنی، برنامه کامپایل میشه ولی یه وارنینگ میگیری:

```console
$ cargo build

warning: unused `Result` that must be used
  --> src/main.rs:10:5
   |
10 |     io::stdin().read_line(&mut guess);
   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
   |

   = note: `#[warn(unused_must_use)]` (part of `#[warn(unused)]`) on by default
help: use `let _ = ...` to ignore the resulting value
   |
```

بعد ببین اصلا `Rust` داره بهت هشدار میده که تو از مقدار `Result` که `read_line` برگردونده استفاده نکردی، یعنی برنامه یه خطای احتمالی رو هندل نکرده.

خب، اگه داری از دنیای تایپ اسکریپت و اینجور زبان ها میای بذار تکلیفتو همینجا روشن کنم!

راه خلاص شدن از این وارنینگ اینه که واقعا واقعا مثل آدم کد مدیریت خطا بنویسی، ولی توی کیس ما اصلا میخوایم برنامه وقتی به مشکل خورد کرش کنه، پس همون `expect` کافیه. توی چپتر ۹ بهت میگم چطوری ازین خطاها ریکاور کنی و اینجا فقط برای یادگیریه، حواست باشه بعدا نری شت کد بزنی بندازی گردن من. 

### چاپ کردن مقادیر با پلیس‌هولدرهای `println!`

به جز آکولاد بسته، فقط یه لاین دیگه از کد مونده که راجع بهش حرف بزنیم:


```rust
    println!("You guessed: {guess}");
```

این لاین، میاد اون رشته‌ ای که الان `input`ـه کاربر رو داخلش داره، برات چاپ میکنه. 

اون جفت آکولاد `{}` یه پلیس‌ هولدر (`placeholder`) هست.

شما وقتی داری مقدار یه متغیر رو چاپ میکنی، میتونی اسم متغیر رو مستقیم بذاری داخل اون آکولاد ها.

ولی وقتی میخوای نتیجه‌ی یه اکسپرشن رو چاپ کنی، آکولاد هارو خالی میذاری و بعد از رشته‌ی فرمت، اکسپرشن هارو با کاما جدا میکنی و به همون ترتیب مینویسی.

چاپ کردن یه متغیر و نتیجه‌ی یه اکسپرشن توی یه `println!` اینجوری میشه:

```rust
let x = 5;
let y = 10;

println!("x = {x} and y + 2 = {}", y + 2);
```

خروجی این کد میشه `x = 5 and y + 2 = 12`.

### تست کردن بخش اول

خب پدرمان تا اینجا در آمد و تازه رسیدیم به نصف این چپتر. بیا بریم بخش اول بازی رو تست کنیم. 

یه `cargo run` بزن ببین چند چندیم:


## ساختن عدد مخفی

قدم بعدی اینه که یه عدد مخفی تولید کنیم تا کاربر بره حدسش بزنه.

این عدد باید هر بار متفاوت باشه، وگرنه بازی بار دوم دیگه بی معنی میشه کلا. ما یه عدد رندوم بین ۱ تا ۱۰۰ انتخاب میکنیم که بازی خیلی هم سخت نشه و سریع بتونیم تست بگیریم.

حالا `Rust` فعلا امکانات تولید عدد رندوم رو توی استاندارد لایبریش نداره، ولی خود تیم `Rust` یه کریت به اسم [`rand`](https://crates.io/crates/rand) داره که کارو برامون در میاره.

### اضافه کردن قابلیت با یه کریت

یادت باشه که یه کریت (`crate`) در واقع یه مجموعه از فایل های سورس کد `Rust` هست.

پروژه‌ ای که ما الان داریم میسازیم یه کریت باینری (`binary crate`) هست یعنی یه چیزیه که قابل اجراس. 

ولی `rand` یه کریت لایبری (`library crate`) هست، یعنی کدی که قراره داخل برنامه های دیگه استفاده بشه و خودش به تنهایی اجرا نمیشه!!

یادته گفتم که یکی از دلایل استفاده از کارگو، مدیریت کریت های `external` هست؟ اینجا دقیقا همون جاییه که کارگو میاد کارو راحت میکنه و ما هم اون موقع حرف زدیم راجع بهش.

حالا قبل از اینکه بتونیم از `rand` استفاده کنیم، باید فایل `Cargo.toml` رو ویرایش کنیم و `rand` رو به عنوان یه `dependency` بهش اضافه کنیم.

اون فایله رو باز کن و این خط رو زیر هدر `[dependencies]` که `Cargo` برات ساخته اضافه کن. 

حواست باشه دقیقا همین ورژنی که اینجا نوشتم رو اونجا بنویسی، وگرنه ممکنه مثال های این چپتر برات کار نکنه:


<span class="filename">نام فایل: Cargo.toml</span>

```toml
[dependencies]
rand = "0.10.1"
```

توی فایل `Cargo.toml` هرچی بعد از یه هدر بیاد، بخشی از همون سکشن حساب میشه تا وقتی که سکشن بعدی شروع بشه.

توی `[dependencies]` به `Cargo` میگی پروژت به چه کریت های اکسترنالی و چه ورژن هایی از اونا نیاز داره. 

اینجا ما `rand` رو با ورژن `0.10.1` مشخص کردیم.

بعد این `Cargo` استاندارد [`Semantic Versioning`](http://semver.org) رو حالیشه (که بهش `SemVer` هم میگن) و این یه استاندارد برای نوشتن شماره ورژنه.

در واقع `0.10.1` خلاصه‌ شده‌ی `^0.10.1` هست، یعنی هر ورژنی که حداقل `0.10.1` باشه ولی زیر `0.11.0` بمونه.

از نظر `Cargo` این ورژن ها `API` سازگار با `0.10.1` دارن، و این باعث میشه تو آخرین پچی رو بگیری که هنوزم با کدهای این چپتر کامپایل میشه، هر ورژن `0.11.0` به بالا هم طبیعتا تضمینی نداره که همون `API` رو داشته باشه.

حالا بدون اینکه هیچ کدی رو تغییر بدیم، بیا پروژه رو بیلد کنیم، مثل لیستینگ ۲-۲:

```console
$ cargo build
    Updating crates.io index
     Locking 8 packages to latest Rust 1.96.0 compatible versions
  Downloaded rand_core v0.10.1
  Downloaded chacha20 v0.10.1
  Downloaded rand v0.10.1
  Downloaded 3 crates (162.9KiB) in 0.59s
   Compiling libc v0.2.186
   Compiling rand_core v0.10.1
   Compiling getrandom v0.4.3
   Compiling cfg-if v1.0.4
   Compiling chacha20 v0.10.1
   Compiling rand v0.10.1
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 2.03s
```

<span class="caption">لیستینگ ۲-۲: خروجی `cargo build` بعد از اضافه کردن کریت `rand` به عنوان دپندنسی</span>

حالا شما ممکنه شماره ورژن های متفاوتی ببینی (که همشون به لطف `SemVer` با کد ما سازگارن) یا لاین های متفاوتی (بسته به سیستم عاملت) و حتی ترتیب لاین ها هم ممکنه فرق کنه ولی مقصود یکی هست عزیزم!

وقتی یه دپندنسی اکسترنال اضافه میکنیم، `Cargo` میره آخرین ورژن هر چیزی که اون دپندنسی لازم داره رو از `registry` میگیره. این `registry` هم یه کپی از داده های [Crates.io](https://crates.io/) هست یعنی همون جایی که آدم های اکوسیستم `Rust` پروژه های اوپن سورسشون رو میذارن تا بقیه ازش استفاده کنن.

بعد از آپدیت کردن `registry`، کارگو سکشن `[dependencies]` رو چک میکنه و هر کریتی که هنوز دانلود نشده باشه رو دانلود میکنه.

حالا توی این مورد، ما فقط `rand` رو نوشته بودیم، ولی کارگو یه سری کریت دیگه که خود `rand` بهشون نیاز داره رو هم آورد. 

بعد از دانلود، `Rust` همشون رو کامپایل میکنه و بعد پروژه رو با این دپندنسی ها کامپایل میکنه.

حالا اگه بلافاصله دوباره `cargo build` بزنی بدون اینکه چیزی رو عوض کرده باشی، هیچ خروجی به جز خط `Finished` نمیبینی چون کارگو میدونه که آلردی دپندنسی هارو دانلود و کامپایل کرده، و تو هم توی `Cargo.toml` چیزیشون رو عوض نکردی. 

ضمن اینکه میدونه کد خودتم تغییری نکرده، پس اونم دوباره کامپایل نمیکنه. وقتی کاری برای انجام دادن نباشه، فقط از برنامه خارج میشه.

حالا اگه فایل `src/main.rs` رو باز کنی، یه تغییر کوچولو بدی، سیوش کنی و دوباره بیلد بگیری، فقط دو خط خروجی میبینی:

```console
$ cargo build
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.13s
```

این خط ها نشون میدن که کارگو فقط بیلد رو با همون تغییر کوچیک تو آپدیت کرده. دپندنسی هات عوض نشدن، پس کارگو میدونه که میتونه همون چیزی که قبلا دانلود و کامپایل کرده رو دوباره استفاده کنه.

#### بیلد های تکرارپذیر (`reproducible builds`)

این کارگو یه مکانیزمی داره که مطمئن میشه هر بار تو یا هر کس دیگه ای کدتو بیلد کنه، دقیقا همون خروجی یکسان ساخته بشه. 

یعنی کارگو فقط از همون ورژن هایی از دپندنسی ها استفاده میکنه که تو مشخص کردی مگه اینکه خودت بیای خلافش رو بگی.

مثلا فرض کن هفته بعد ورژن `0.10.2` از کریت `rand` بیاد بیرون و توش یه باگ فیکس مهم باشه، ولی همزمان یه رگرشن هم داشته باشه که کد تو رو به فنا میده.

برای همینه که `Rust` اولین باری که `cargo build` میزنی، فایل `Cargo.lock` رو میسازه، پس الان این فایل رو داخل دایرکتری `guessing_game` داریم.

وقتی برای اولین بار پروژه رو بیلد میکنی، کارگو تمام ورژن هایی که با شرایط تو جور در میان رو پیدا میکنه و مینویسه توی `Cargo.lock`.

دفعه های بعدی که بیلد میگیری، کارگو میبینه فایل `Cargo.lock` وجود داره و به جای اینکه دوباره کل کار پیدا کردن ورژن هارو انجام بده، از همونایی که اونجا نوشته شده استفاده میکنه. اینجوری بیلدت به صورت خودکار تکرارپذیر میشه.

بخوام ساده بگم، پروژه‌ شما به لطف `Cargo.lock` روی `0.10.1` قفل میشه تاااااا وقتی که خودت صراحتا آپگریدش کنی و تغییرش بدی، و چون این فایل برای تکرارپذیری خیلی مهمه معمولا کنار بقیه کد پروژه توی گیت هم کامیت میشه.

#### آپدیت کردن یه کریت به ورژن جدید

حالا وقتی که واقعا خودت بخوای یه کریت رو آپدیت کنی، کارگو دستور `update` رو داره.

این دستور فایل `Cargo.lock` رو به یه ورش میگیره و آخرین ورژن هایی که با شرط های `Cargo.toml` جور در میان رو پیدا میکنه بعد اونارو مینویسه توی `Cargo.lock`.

در غیر این صورت، کارگو به صورت پیشفرض فقط دنبال ورژن های بالاتر از `0.10.1` و پایین تر از `0.11.0` میگرده. 

شما الان فرض کن کریت `rand` دو تا ورژن جدید `0.10.2` و `0.999.0` منتشر کرده باشه، اگه `cargo update` بزنی همچین چیزی میبینی:

```console
$ cargo update
    Updating crates.io index
     Locking 1 package to latest Rust 1.96.0 compatible version
    Updating rand v0.10.1 -> v0.10.2 (available: v0.999.0)
```

میبینی که کارگو ورژن `0.999.0` رو نادیده گرفت. الان اگه فایل `Cargo.lock` رو نگاه کنی، میبینی که ورژن `rand` شده `0.10.2`.

اگه بخوای از `rand` ورژن `0.999.0` یا هر ورژنی از سری `0.999` استفاده کنی، باید `Cargo.toml` رو اینجوری تغییر بدی (حالا الان واقعا این کارو نکن، چون مثال های بعدی فرض میکنن که تو داری از `rand` نسخه `0.10` استفاده میکنی):

```toml
[dependencies]
rand = "0.999.0"
```

دفعه بعد که `cargo build` بزنی، کارگو `registry` رو آپدیت میکنه و شرط های `rand` تو رو بر اساس ورژن جدیدی که مشخص کردی دوباره بررسی میکنه.

راجع به [کارگو](https://doc.rust-lang.org/cargo/) و [اکوسیستمش](https://doc.rust-lang.org/cargo/reference/publishing.html) خیلی حرف ها هست که توی چپتر ۱۴ بهشون میپردازم، ولی فعلا همینقدر کافیه.

کلا الان یاد گرفتی که کارگو استفاده دوباره از لایبری هارو خیلی راحت میکنه و برای همینم دولپر ها میتونن پروژه های کوچیک تری بنویسن که از کنار هم گذاشتن چندتا پکیج ساخته شدن.

### تولید کردن یه عدد رندوم

بعد اینهمه حرف، بیا بریم از `rand` استفاده کنیم تا یه عدد برای حدس زدن بسازیم. 

قدم بعدی آپدیت کردن `src/main.rs` هست، مثل لیستینگ ۲-۳:

<span class="filename">نام فایل: src/main.rs</span>

```rust
use std::io;

use rand::prelude::*;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    println!("The secret number is: {secret_number}");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}
```

<span class="caption">لیستینگ ۲-۳: اضافه کردن کد برای تولید یه عدد رندوم</span>

اول از همه، خط `use rand::prelude::*;` رو اضافه کردیم. ماژول `prelude` پرکاربردترین بخش های کریت `rand` رو داخل خودش داره و `use` هم اونارو میاره توی اسکوپ برنامه‌ ما.

بعدش دو تا خط وسط کد اضافه کردیم.

توی خط اول، فانکشن `rand::rng` رو صدا میزنیم که یه چی بهمون میده که عدد رندوم تولید میکنه. این تولیدکننده (اسم بهتر پیدا نمیکنم ناموسن) مخصوص همون `thread` جاری برنامس و سیستم عامل بهش `seed` میده.

بعد متد `random_range` رو روی همین تولیدکننده صدا میزنیم. این متد توسط تریت (`trait`) به اسم `RngExt` تعریف شده که بخشی از همون ماژول `rand::prelude` هست که با `use rand::prelude::*;` آوردیمش توی اسکوپ.

متد `random_range` یه اکسپرشن رنج (`range`) به عنوان آرگومان میگیره و یه عدد رندوم توی اون رنج یا بازه تولید میکنه.

شکل `range‍`ـی که ما اینجا استفاده کردیم به فرم `start..=end` هست و هم کران پایین و هم کران بالا رو شامل میشه، پس ما برای گرفتن یه عدد بین ۱ تا ۱۰۰ باید بنویسیم `1..=100`.

> شما قرار نیست خود به‌ خود بدونی از یه کریت چی رو باید بیاری توی اسکوپ یا چه متد و فانکشنی رو صدا بزنی. هر کریتی مستندات خودشو داره که توش نوشته چطوری ازش استفاده کنی. یه فیچر باحال دیگه کارگو هم اینه که با دستور `cargo doc --open` مستندات تمام دپندنسی هات رو به صورت لوکال بیلد میکنه و توی مرورگرت باز میکنه.

لاین جدید دوم هم عدد مخفی رو چاپ میکنه. این موقع توسعه به دردمون میخوره که بتونیم برنامه رو تست کنیم، ولی بعدا توی نسخه نهایی پاکش میکنیم. 

وگرنه که بازی همون اول جواب رو لو میده و دیگه بازی نیست! :))))

## مقایسه کردن حدس با عدد مخفی

حالا که هم ورودی کاربر رو داریم و هم عدد رندوم، میتونیم بشینیم مقایسشون کنیم. 

این قدم توی لیستینگ ۲-۴ اومده. فقط حواست باشه که این کد فعلا کامپایل نمیشه و دلیلش رو هم توضیح میدیم.

<span class="filename">نام فایل: src/main.rs</span>

<img class="ferris" src="/img/ferris/does_not_compile.svg" alt="این کد کامپایل نمی‌شود!" title="این کد کامپایل نمی‌شود!" />

```rust
use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

fn main() {
    // --snip--

    println!("You guessed: {guess}");

    match guess.cmp(&secret_number) {
        Ordering::Less => println!("Too small!"),
        Ordering::Greater => println!("Too big!"),
        Ordering::Equal => println!("You win!"),
    }
}
```

<span class="caption">لیستینگ ۲-۴: هندل کردن حالت های ممکن موقع مقایسه دو تا عدد</span>

اول یه `use` دیگه اضافه کردیم و یه تایپ به اسم `std::cmp::Ordering` رو از استاندارد لایبری آوردیم توی اسکوپ.

تایپ `Ordering` هم یه `enum` دیگس و ورینت هاش `Less` و `Greater` و `Equal` هستن و اینا همون سه تا حالتیه که وقتی دو تا مقدار رو مقایسه میکنی ممکنه پیش بیاد.

بعدش پنج خط جدید ته کد اضافه کردیم که از `Ordering` استفاده میکنن.

متد `cmp` دو تا مقدار رو مقایسه میکنه و روی هر چیزی که قابل مقایسه باشه صدا زده میشه. 

این متد میاد یه رفرنس به چیزی که میخوای باهاش مقایسه کنی رو میگیره، اینجا `guess` رو با `secret_number` مقایسه میکنه و بعدشم یکی از ورینت های `Ordering` رو برمیگردونه.

ما هم از یه اکسپرشن [`match`](ch06-02-match.md) استفاده میکنیم تا بر اساس اینکه `cmp` کدوم ورینت رو برگردونده، تصمیم بگیریم قدم بعدی چیه.

یه اکسپرشن `match` از یه سری بازو (`arm`) تشکیل شده. هر بازو یه پترن داره که باید باهاش مطابقت بشه، به علاوه‌ی کدی که اگه مقدار داده شده به `match` با اون پترن جور در اومد اجرا میشه.

بعد هم`Rust` مقداری که به `match` دادی رو برمیداره و به ترتیب پترن هر بازو رو چک میکنه.

الگو ها و ساختار `match` از فیچر های خیییلی خیلی قدرتمند `Rust` هستن و بهت اجازه میدن انواع موقعیت هایی که ممکنه کدت باهاش روبرو بشه رو بیان کنی و مطمئن هم میشن که تو همشون رو هندل کردی. اینارو به ترتیب توی چپتر ۶ و چپتر ۱۹ مفصل توضیح میدم.

بیا با یه مثال همین `match` که اینجا نوشتیم رو قدم به قدم بریم جلو. فرض کن کاربر ۵۰ رو حدس زده و عدد مخفی این دفعه ۳۸ بوده.

وقتی کد ۵۰ رو با ۳۸ مقایسه میکنه، متد `cmp` مقدار `Ordering::Greater` رو برمیگردونه چون ۵۰ بزرگتر از ۳۸ هست.

اکسپرشن `match` این مقدار `Ordering::Greater` رو میگیره و شروع میکنه الگوی هر بازو رو چک کردن. اول الگوی بازوی اول یعنی `Ordering::Less` رو نگاه میکنه و میبینه که `Ordering::Greater` با `Ordering::Less` جور در نمیاد، پس کد اون بازو رو نادیده میگیره و میره سراغ بازوی بعدی.

الگوی بازوی بعدی `Ordering::Greater` هست، که این دفعه جور در میاد! پس کد همون بازو اجرا میشه و `Too big!` رو روی صفحه چاپ میکنه.

اکسپرشن `match` بعد از اولین تطابق موفق تموم میشه، پس توی این سناریو اصلا بازوی آخر رو نگاه هم نمیکنه.

راست یه سیستم تایپ قوی و استاتیک داره (عمده دلیلی که اصلا من اومدم سمتش همینه)، ولی در عین حال استنتاج تایپ (`type inference`) هم داره.

وقتی ما نوشتیم `let mut guess = String::new()`، خود `Rust` تونست حدس بزنه که `guess` باید یه `String` باشه و مجبورمون نکرد که تایپش رو بنویسیم.

ولی `secret_number` یه تایپ عددیه. چندتا از تایپ های عددی `Rust` میتونن یه مقدار بین ۱ تا ۱۰۰ رو نگه دارن: `i32` که یه عدد ۳۲ بیتیه، `u32` که یه عدد ۳۲ بیتی بدون علامته، `i64` که ۶۴ بیتیه و چندتا دیگه.

مگه اینکه خودت جور دیگه ای مشخص کنی، `Rust` به صورت پیشفرض `i32` انتخاب میکنه، پس تایپ `secret_number` هم همینه (مگه اینکه یه جای دیگه اطلاعات تایپی اضافه کنی که باعث بشه `Rust` یه تایپ عددی دیگه استنتاج کنه).

پس دلیل ارور اینه که `Rust` نمیتونه یه رشته رو با یه عدد مقایسه کنه.

در نهایت ما میخوایم اون `String` که به عنوان ورودی خوندیم رو به یه تایپ عددی تبدیل کنیم تا بتونیم عددی با عدد مخفی مقایسش کنیم. 

برای این کار این خط رو به بدنه‌ی `main` اضافه میکنیم:

چرا داشت ولی `Rust` این لطف رو بهمون میکنه و میذاره مقدار قبلی `guess` رو با یه مقدار جدید ‍`shadow` کنیم و واقعا ماچ به کله اش!

این `shadowing` بهمون اجازه میده اسم `guess` رو دوباره استفاده کنیم و 

با استفاده ازین `shadowing`، ما به جای اینکه مجبور بشیم دو تا متغیر جدا با اسم های مثلا `guess_str` و `guess` بسازیم، بیایم همون `guess` رو دوباره استفاده کنیم.

این مبحث رو توی چپتر ۳ کامل تر توضیح میدم ولی فعلا اینو بدون که این فیچر معمولا وقتی به کار میاد که بخوای یه مقدار رو از یه تایپ به تایپ دیگه تبدیل کنی.

حالا این متغیر جدید رو به اکسپرشن `guess.trim().parse()` بایند میکنیم. اون `guess` که داخل اکسپرشن هست به همون متغیر `guess` اصلی اشاره میکنه که ورودی رو به شکل رشته توش داشتیم.

متد `trim` روی یه `String` هر فاصله‌ی خالی اول و آخر رشته رو پاک میکنه. این کار حتما باید انجام بشه قبل از اینکه رشته رو به `u32` تبدیل کنیم، چون `u32` فقط داده عددی قبول میکنه.

حالا کاربر برای اینکه `read_line` رو تموم کنه و حدسش سابمیت بشه، باید <kbd>enter</kbd> بزنه، و همین باعث میشه یه کاراکتر خط جدید (`newline`) به رشته اضافه بشه.

مثلا اگه کاربر <kbd>5</kbd> رو تایپ کنه و <kbd>enter</kbd> بزنه، مقدار `guess` میشه `5\n`. اون `\n` یعنی «خط جدید». (روی ویندوز زدن <kbd>enter</kbd> باعث میشه `\r\n` اضافه بشه.)

متد `trim` این `\n` یا `\r\n` رو پاک میکنه و فقط `5` باقی میمونه.

متد [`parse` روی رشته ها](https://doc.rust-lang.org/std/primitive.str.html#method.parse) هم یه رشته رو به یه تایپ دیگه تبدیل میکنه. اینجا ما ازش استفاده کردیم تا از رشته به عدد تبدیل کنیم.

ما باید دقیقا به `Rust` بگیم چه تایپ عددی میخوایم، برای همین نوشتیم `let guess: u32`. اون دو نقطه (`:`) بعد از `guess` به `Rust` میگه که میخوایم تایپ متغیر رو مشخص کنیم.

راست چندتا تایپ عددی اینترنال داره و همین `u32` که اینجا میبینی یه عدد صحیح ۳۲ بیتی بدون علامته مثبت منفیه و برای عدد های مثبت کوچیک انتخاب دیفالت خوبیه. 

بقیه تایپ های عددی رو توی چپتر ۳ بهت میگم.

یه نکته دیگه هم اینکه چون اینجا تایپ `u32` رو مشخص کردیم و بعدش با `secret_number` مقایسه کردیم، `Rust` استنتاج میکنه که `secret_number` هم باید `u32` باشه. پس الان مقایسه بین دو تا مقدار از یه تایپ انجام میشه!

متد `parse` فقط روی کاراکتر هایی کار میکنه که منطقا بشه به عدد تبدیلشون کرد پس خیلی راحت ممکنه به ارور بخوره و مثلا اگه رشته `A👍%` باشه، اصلا راهی نیست که بشه تبدیلش کرد به عدد.

چون ممکنه `fail` بشه، `parse` هم یه تایپ `Result` برمیگردونه، دقیقا مثل `read_line` (که بالاتر توی بخش «مدیریت خطاهای احتمالی با `Result`» راجع بهش حرف زدیم).

حالا ما هم با این `Result` دقیقا مثل قبل برخورد میکنیم و دوباره از متد `expect` استفاده میکنیم.

اگه `parse` ورینت `Err` رو برگردونه چون نتونسته از رشته یه عدد بسازه، `expect` بازی رو کرش میکنه و همون پیامی که بهش دادیم رو چاپ میکنه. ولی اگه `parse` بتونه با موفقیت رشته رو به عدد تبدیل کنه، ورینت `Ok` رو برمیگردونه و `expect` هم عددی که میخوایم رو از داخل `Ok` درمیاره و بهمون میده.

### هندل کردن ورودی نامعتبر

بیا رفتار بازی رو یه ذره بهتر کنیم. به جای اینکه وقتی کاربر یه چیز غیر عددی وارد کرد برنامه کرش کنه، بیا کاری کنیم که بازی اون ورودی رو نادیده بگیره تا کاربر بتونه به حدس زدن ادامه بده.

برای این کار خطی که `guess` رو از `String` به `u32` تبدیل میکنه رو عوض میکنیم، مثل لیستینگ ۲-۵:

<span class="filename">نام فایل: src/main.rs</span>

```rust
        // --snip--

        io::stdin()
            .read_line(&mut guess)
            .expect("Failed to read line");

        let guess: u32 = match guess.trim().parse() {
            Ok(num) => num,
            Err(_) => continue,
        };

        println!("You guessed: {guess}");

        // --snip--
```

<span class="caption">لیستینگ ۲-۵: نادیده گرفتن حدس غیر عددی و درخواست یه حدس جدید به جای کرش کردن برنامه</span>

ما `expect` رو با یه اکسپرشن `match` عوض کردیم تا از «کرش موقع ارور» به «هندل کردن ارور» برسیم.

یادت باشه که `parse` یه `Result` برمیگردونه و `Result` هم یه `enum` هست که ورینت های `Ok` و `Err` داره. اینجا هم دقیقا مثل کاری که با نتیجه `Ordering` از متد `cmp` کردیم، از `match` استفاده میکنیم.

اگه `parse` بتونه رشته رو با موفقیت به عدد تبدیل کنه، یه مقدار `Ok` برمیگردونه که عدد نهایی داخلشه. این مقدار `Ok` با پترن بازوی اول جور در میاد و اکسپرشن `match` هم فقط همون مقدار `num` که `parse` تولید کرده و گذاشته داخل `Ok` رو برمیگردونه. اون عدد هم دقیقا میره همون جایی که میخوایم، یعنی داخل متغیر `guess` جدیدی که داریم میسازیم.

ولی اگه `parse` نتونه رشته رو به عدد تبدیل کنه، یه مقدار `Err` برمیگردونه که اطلاعات بیشتری راجع به ارور داخلشه.

این مقدار `Err` با الگوی `Ok(num)` توی بازوی اول جور در نمیاد، ولی با الگوی `Err(_)` توی بازوی دوم جور در میاد.

اون آندرلاین یعنی `_` یه مقدار گلوباله و توی این مثال داریم میگیم میخوایم تمام مقادیر `Err` رو بگیریم فرقی نداره چه اطلاعاتی داخلشون باشه.

پس برنامه کد بازوی دوم یعنی `continue` رو اجرا میکنه، که به برنامه میگه برو سراغ تکرار بعدی `loop` و دوباره یه حدس بخواه. در عمل، برنامه هر خطایی که `parse` ممکنه بهش بخوره رو نادیده میگیره!

<span class="filename">نام فایل: src/main.rs</span>

```rust
use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    loop {
        println!("Please input your guess.");

        let mut guess = String::new();

        io::stdin()
            .read_line(&mut guess)
            .expect("Failed to read line");

        let guess: u32 = match guess.trim().parse() {
            Ok(num) => num,
            Err(_) => continue,
        };

        println!("You guessed: {guess}");

        match guess.cmp(&secret_number) {
            Ordering::Less => println!("Too small!"),
            Ordering::Greater => println!("Too big!"),
            Ordering::Equal => {
                println!("You win!");
                break;
            }
        }
    }
}
```

## جمع بندی

این پروژه یه راه عملی بود که بتونم کلی مفهوم جدید `Rust` رو بهت معرفی کنم: `let`، `match`، فانکشن ها، استفاده از کریت های اکسترنال و یه سری چیز دیگه.

حالا توی چپتر های بعدی همه اینارو با جزئیات بیشتر یاد میگیری.

چپتر ۳ راجع به مفاهیمیه که تقریبا توی همه زبان های برنامه‌نویسی هست مثل متغیر ها، دیتا تایپ ها و فانکشن ها و بهت میگم که توی `Rust` چطوری ازشون استفاده کنیم.

چپتر ۴ سراغ مالکیت یا همون `ownership` میریم و این تقریبا فیچریه که `Rust` رو از بقیه زبان ها متمایز میکنه.

چپتر ۵ هم درباره استراکت ها (`structs`) و سینتکس متد ها حرف میزنه و چپتر ۶ هم توضیح میده که `enum` ها چطوری کار میکنن.
