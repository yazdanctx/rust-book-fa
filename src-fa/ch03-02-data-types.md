هر مقداری توی `Rust` یه `data type` مشخص داره که به `Rust` میگه با چه نوع داده ای طرفه و اینجوری `Rust` میفهمه که چطوری باید با اون متغیر کار کنه. 

ما الان قراره دو تا زیرمجموعه از دیتا تایپ هارو ببینیم: `scalar` و `compound`.

یادت باشه که `Rust` یه زبان با تایپ استاتیک (`statically typed`) هست یعنی `Rust` موقع کامپایل باید تایپ همه متغیر هارو بدونه.

حالا خود کامپایلر هم معمولا میتونه بر اساس مقدار و نحوه استفادمون، تایپی که میخوایم رو استنتاج کنه. ولی این در خیلی از حالات ممکن نیست یه نمونه بارزش میشه مثل همون موقعی که توی بخش مقایسه کردن حدس با عدد مخفی از [چپتر ۲](ch02-00-guessing-game-tutorial.md) یه `String` رو با `parse` به یه تایپ عددی تبدیل کردیم و خودمون باید تایپ رو مشخص کنیم. 

حالا اگه یادت رفته یا اون چپتر رو نخوندی، من دارم راجع به اینجا حرف میزنم:

```rust

```

### تایپ های اسکالر

زبان `Rust` چهار تا تایپ اسکالر اصلی داره: عدد صحیح (`integer`)، عدد اعشاری (`floating-point`)، بولین (`Boolean`) و کاراکتر (`character`).

احتمالا اینارو از زبان های دیگه میشناسی چون خیلی پرکاربرد هستن پس من مستقیم میرم سراغ اینکه توی `Rust` چطوری کار میکنن.

#### تایپ های عدد صحیح

عدد صحیح یعنی عددی که بخش اعشاری نداره. توی چپتر ۲ از یکی از تایپ های عدد صحیح استفاده کردیم، یعنی `u32`.

این تایپ میگه مقداری که بهش وصله باید یه عدد صحیح بدون علامت (`unsigned`) باشه که ۳۲ بیت فضا میگیره 

> تایپ های علامت دار به جای `u` با `i` شروع میشن.

جدول ۳-۱ تایپ های عدد صحیحی که توی `Rust` تعبیه شدن رو نشون میده و ما میتونیم از هر کدوم از این ورینت ها برای تعریف تایپ یه عدد صحیح استفاده کنیم.

<span class="caption">جدول ۳-۱: تایپ های عدد صحیح توی `Rust`</span>

| طول  | علامت دار  | بدون علامت |
| ------- | ------- | -------- |
| ۸ بیت   | `i8`    | `u8`     |
| ۱۶ بیت  | `i16`   | `u16`    |
| ۳۲ بیت  | `i32`   | `u32`    |
| ۶۴ بیت  | `i64`   | `u64`    |
| ۱۲۸ بیت | `i128`  | `u128`   |
| وابسته به معماری سیستم | `isize` | `usize`  |

هر ورینت میتونه علامت دار (`signed`) یا بدون علامت (`unsigned`) باشه و یه سایز مشخصی هم داره.

علامت دار و بدون علامت یعنی اینکه آیا امکانش هست عدد منفی بشه یا نه. به عبارت دیگه، آیا عدد نیاز داره که یه علامت همراهش باشه یا همیشه فقط مثبته و میشه بدون علامت نشونش داد.

این اصلا مثل همون نوشتن عدد روی کاغذه و وقتی علامت مهمه، شما عدد رو با یه علامت مثبت یا منفی مینویسی ولی وقتی خیالت راحته که عدد مثبته، بدون علامت مینویسیش. عدد های علامت دار هم با روش [مکمل دو (`two's complement`)](https://en.wikipedia.org/wiki/Two%27s_complement) ذخیره میشن.

هر ورینت علامت دار میتونه عدد های از −(2<sup>n − 1</sup>) تا 2<sup>n − 1</sup> − 1 رو نگه داره که `n` تعداد بیت های اون ورینته. پس یه `i8` میتونه عدد های از −(2<sup>7</sup>) تا 2<sup>7</sup> − 1 رو نگه داره که میشه ۱۲۸− تا ۱۲۷.

ورینت های بدون علامت هم میتونن از 0 تا 2<sup>n</sup> − 1 رو نگه دارن، پس یه `u8` میتونه از 0 تا 2<sup>8</sup> − 1 رو ذخیره کنه که میشه ۰ تا ۲۵۵.

اون دو تا تایپ `isize` و `usize` هم به معماری کامپیوتری که برنامت روش اجرا میشه بستگی دارن: اگه روی معماری ۶۴ بیتی باشی ۶۴ بیت هستن و اگه روی معماری ۳۲ بیتی باشی ۳۲ بیت.

بعد شما `integer literals` رو میتونی به هر کدوم از شکل های جدول ۳-۲ بنویسی.

یه نکته اینکه `integer literal` هایی که میتونن چند تایپ عددی مختلف باشن، اجازه دارن یه پسوند تایپ بگیرن (مثل `57u8`) تا تایپشون مشخص بشه. `integer literal` های عددی همچنین میتونن از `_` به عنوان جداکننده بصری استفاده کنن تا خوندن عدد راحت تر بشه مثل `1_000` که دقیقا همون مقدار `1000` رو داره.

<span class="caption">جدول ۳-۲: لیترال های عدد صحیح توی `Rust`</span>

| لیترال عددی  | مثال       |
| ---------------- | ------------- |
| دهدهی (`Decimal`)          | `98_222`      |
| مبنای ۱۶ (`Hex`)              | `0xff`        |
| مبنای ۸ (`Octal`)            | `0o77`        |
| باینری (`Binary`)           | `0b1111_0000` |
| بایت (فقط `u8`) | `b'A'`        |

خب حالا از کجا بدونی کدوم تایپ عدد صحیح رو باید استفاده کنی؟ اگه مطمئن نیستی، پیشفرض های `Rust` معمولا اوکی هستن + تایپ های عدد صحیح به صورت پیشفرض `i32` هستن.

> #####  `Integer Overflow`

> فرض کن یه متغیر از تایپ `u8` داری که میتونه مقادیر بین ۰ تا ۲۵۵ رو نگه داره. اگه سعی کنی متغیر رو به یه مقدار خارج از این بازه تغییر بدی، مثلا ۲۵۶، اونوقت `integer overflow` اتفاق میفته که میتونه به یکی از این دو رفتار ختم بشه.
>
> وقتی داری توی حالت دیباگ کامپایل میکنی، `Rust` یه سری چک برای `integer overflow` میذاره که اگه این اتفاق بیفته، برنامت موقع اجرا پنیک (`panic`) میکنه. `Rust` از اصطلاح پنیک وقتی استفاده میکنه که یه برنامه با ارور خارج میشه و پنیک هارو با جزئیات بیشتر توی بخش [«خطاهای جبران‌ناپذیر با `panic!`»](ch09-01-unrecoverable-errors-with-panic.md) از چپتر ۹ بررسی میکنیم.
>
> ولی وقتی داری با فلگ `--release` توی حالت `release` کامپایل میکنی، `Rust` دیگه این چک های `integer overflow` که پنیک میکنن رو نمیذاره و به جاش اگه `integer overflow` اتفاق بیفته، `Rust` عمل چرخش مکمل دو (`two's complement wrapping`) رو انجام میده.
>
> حالا چرخش مکمل دو یعنی چی؟؟ خلاصه اش اینه که مقادیر بزرگ تر از حداکثری که تایپ میتونه نگه داره، **میچرخن** و تبدیل میشن به حداقل مقدار اون تایپ! مثلا توی مورد `u8`، مقدار ۲۵۶ میشه ۰، مقدار ۲۵۷ میشه ۱ و الی آخر. برنامه پنیک نمیکنه، ولی متغیرت الان یه مقداری رو داره که احتمالا شما انتظارشو داشتی.
>
> برای اینکه احتمال `integer overflow` رو هندل کنی، میتونی از این این متد هایی که استاندارد لایبری برای تایپ های عددی اولیه گذاشته استفاده کنی:
>
> - چرخش توی همه حالت های کامپایل با متد های `wrapping_*` مثل `wrapping_add`.
> - برگردوندن مقدار `None` در صورت `integer overflow` با متد های `checked_*`.
> - برگردوندن مقدار به همراه یه بولین که میگه سرریز شده یا نه، با متد های `overflowing_*`.
> - اشباع شدن روی حداقل یا حداکثر مقدار تایپ با متد های `saturating_*`.

#### تایپ های عدد اعشاری

زبان `Rust` دو تا تایپ اولیه هم برای عدد های اعشاری (`floating-point`) داره.

تایپ های اعشاری `Rust` عبارتن از `f32` و `f64` که به ترتیب ۳۲ بیت و ۶۴ بیت سایز دارن.

تایپ پیشفرض `f64` هست چون روی پردازنده های مدرن سرعتش تقریبا همون سرعت `f32` هست ولی خب دقت بیشتری داره. 

همه تایپ های اعشاری هم که علامت دار هستن.

اینم یه مثال از عدد های اعشاری:

<span class="filename">نام فایل: src/main.rs</span>

```rust
fn main() {
    let x = 2.0; // f64

    let y: f32 = 3.0; // f32
}
```

عدد های اعشاری طبق استاندارد `IEEE-754` نمایش داده میشن.

#### عملیات عددی

زبان `Rust` همه عملیات ریاضی پایه ای که انتظارشو داری رو برای همه تایپ های عددی ساپورت میکنه. 

جمع، تفریق، ضرب، تقسیم و باقیمانده.

تقسیم عدد صحیح به سمت صفر گرد میشه، یعنی بخش اعشاری نتیجه دور ریخته میشه. کد زیر نشون میده هر عملیات عددی رو چطوری توی یه دستور `let` استفاده میکنی:

<span class="filename">نام فایل: src/main.rs</span>

```rust
fn main() {
    // addition
    let sum = 5 + 10;

    // subtraction
    let difference = 95.5 - 4.3;

    // multiplication
    let product = 4 * 30;

    // division
    let quotient = 56.7 / 32.2;
    let truncated = -5 / 3; // Results in -1

    // remainder
    let remainder = 43 % 5;
}
```

هر اکسپرشن توی این دستور ها از یه عملگر ریاضی استفاده میکنه و به یه مقدار واحد میرسه که بعدش به یه متغیر بایند میشه. لیست همه عملگر هایی که `Rust` داره رو میتونی توی [ضمیمه B](https://doc.rust-lang.org/book/appendix-02-operators.html) (توی نسخه انگلیسی کتاب) ببینی.

#### تایپ بولین

مثل بیشتر زبان های برنامه نویسی، تایپ بولین توی `Rust` هم دو تا مقدار ممکن داره: `true` و `false`. 

بولین ها یه بایت سایز دارن و تایپشون هم با `bool` مشخص میشه. مثلا:

<span class="filename">نام فایل: src/main.rs</span>

```rust
fn main() {
    let t = true;

    let f: bool = false; // with explicit type annotation
}
```

اصلی ترین راه استفاده از مقادیر بولین هم شرط ها هستن مثلا یه اکسپرشن `if`. 

طرز کار اکسپرشن های `if` توی `Rust` رو توی بخش [«کنترل جریان»](ch03-05-control-flow.md) توضیح میدم.

#### تایپ کاراکتر

تایپ `char` ابتدایی ترین تایپ الفبایی زبان `Rust` هست:

<span class="filename">نام فایل: src/main.rs</span>

```rust
fn main() {
    let c = 'z';
    let z: char = 'ℤ'; // with explicit type annotation
    let heart_eyed_cat = '😻';
}
```

دقت کن که برخلاف لیترال های رشته که کوتیشن دوتایی میخوان، ما لیترال های `char` رو با کوتیشن تکی مینویسیم.

تایپ `char` توی `Rust` چهار بایت سایز داره و یه مقدار اسکالر یونیکد (`Unicode scalar value`) رو نشون میده که خب معنیش اینه که خیلی بیشتر از `ASCII` رو میتونه پوشش بده.

حروف با اعراب، کاراکتر های چینی و ژاپنی و کره ای، ایموجی ها و `zero-width space` همشون مقادیر معتبر `char` هستن و مقادیر اسکالر یونیکد از `U+0000` تا `U+D7FF` و از `U+E000` تا `U+10FFFF` رو شامل میشن.

بنظرم فعلا همینقدر بدونی کافیه ولی من جلوتر این موضوع رو با جزئیات بیشتر توی [«ذخیره متن انکود شده با `UTF-8` توی رشته ها»](ch08-02-strings.md) از چپتر ۸ برات بررسی خواهم کرد.

### تایپ های مرکب

در زبان راست، `compound type` ها در واقع تایپ هایی هستن که می‌تونن چندتا مقدار رو با هم نگه دارن.

ما دو نوع `compound type` اولیه داریم: تاپل ها (`tuples`) و آرایه ها (`arrays`).

#### تایپ تاپل

تاپل یه راه ساده برای اینه که چندتا مقدار با `type` های مختلف رو کنار هم بذاری و همه‌شون رو داخل یه `compound type` واحد نگه داری. 

حالا این `tuple`ها یه طول ثابت و مشخصی دارن، یعنی وقتی ساختیشون، دیگه نمی‌تونی تعداد آیتم‌هاشون رو بیشتر یا کمتر کنی.

برای ساختن یه `tuple`، مقادیر رو با `,` از هم جدا می‌کنیم و داخل `()` می‌نویسیم. هر `position` داخل `tuple` یه `type` مشخص داره و لازم نیست `type` همه‌ی مقدارها یکی باشه. 

مثلا می‌تونی یه `String`، یه `number` و یه `boolean` رو کنار هم داخل یه `tuple` داشته باشی.

یه مثال ساده از تاپل:

<span class="filename">نام فایل: src/main.rs</span>

```rust
fn main() {
    let tup: (i32, f64, u8) = (500, 6.4, 1);
}
```

بخوام ساده تر بگم، میتونی تاپل رو مثل یه جعبه در نظر بگیری که چندتا مقدار مختلف داخلشه:

```rust
let tup = (500, 6.4, 1);
```

کل `tuple` داخل متغیر `tup` قرار می‌گیره. برای اینکه مقدارهای داخلش رو جدا کنیم، می‌تونیم از `destructuring` استفاده کنیم:

```rust
let (x, y, z) = tup;
```

اینجا Rust مقدارهای `tup` رو به ترتیب جدا می‌کنه: `500` میره داخل `x`، `6.4` میره داخل `y` و `1` میره داخل `z`.

پس وقتی می‌نویسیم:

```rust
println!("The value of y is: {y}");
```

خروجی `6.4` میشه.

در واقع `destructuring` یعنی یه `tuple` رو باز کنیم و مقدارهای داخلش رو جدا جدا داخل متغیرهای مختلف بذاریم.

حالا ما می‌تونیم مستقیما به هر مقدار داخل یه `tuple` هم دسترسی داشته باشیم و برای این کار بعد از اسم `tuple` یه `.` می‌ذاریم و شماره‌ی `index` اون مقدار رو می‌نویسیم:

```rust
fn main() {
    let x: (i32, f64, u8) = (500, 6.4, 1);

    let five_hundred = x.0;

    let six_point_four = x.1;

    let one = x.2;
}
```

اینجا `x` یه `tuple` هست که سه مقدار داره و خب مثل اکثر زبان‌های برنامه‌نویسی، اینجا هم `index` از `0` شروع میشه پس با `x.0` مقدار اول یعنی `500` رو میگیریم، با `x.1` مقدار دوم یعنی `6.4` و با `x.2` مقدار سوم یعنی `1` .

یه نکته‌ی دیگه هم اینه که `tuple` می‌تونه کاملا خالی باشه. به این `tuple` خالی میگن `unit` و با `()` نوشته میشه. معمولا وقتی یه `expression` هیچ مقدار دیگه‌ای برنمی‌گردونه، `Rust` به‌صورت خودکار `()` رو به عنوان `return value` در نظر می‌گیره.

#### تایپ آرایه
یه راه دیگه برای ایجاد مجموعه از مقادیر، استفاده از `array` هست. برخلاف تاپل، همه المان های یه آرایه باید یه تایپ یکسان داشته باشن و نکته دیگه اینکه برخلاف آرایه ها توی بعضی زبان های دیگه، آرایه های `Rust` یه طول ثابتی دارن.

مقادیر یه آرایه رو به شکل یه لیست جدا شده با کاما داخل براکت مینویسیم:

<span class="filename">نام فایل: src/main.rs</span>

```rust
fn main() {
    let a = [1, 2, 3, 4, 5];
}
```

این `array` برای زمانی خوبه که بخوای یه تعداد مشخصی از مقادیر رو کنار هم نگه داری و مطمئن باشی که تعدادشون هیچ‌وقت تغییر نمی‌کنه. 

> نکته فرعی اینکه آرایه ها روی `stack` ذخیره میشن، نه `heap`، ولی فعلا لازم نیست خیلی درگیر تفاوت این دوتا بشی.

حالا یه چی دیگه هم هست به اسم `vector` که تقریبا شبیه `array` هست، با این تفاوت که می‌تونه در طول برنامه بزرگتر یا کوچیک تر بشه، یعنی اگه نمیدونی که تعداد آیتم‌ها قراره ثابت بمونه یا نه، معمولا `vector` انتخاب بهتریه.

مثلاً تعداد ماه‌های سال همیشه `12` تاست، پس برای نگه‌داشتنشون می‌تونیم از یه `array` استفاده کنیم:

```rust
let months = ["January", "February", "March", "April", "May", "June", "July",
              "August", "September", "October", "November", "December"];
```

اینجا `months` یه `array` با دقیقاً `12` تا عنصره و اندازه‌ش بعدا تغییر نمی‌کنه.

برای مشخص کردن `type` یه `array`، داخل اون `[]` اول `type` هر عنصر رو می‌نویسیم، بعد یه `;` می‌ذاریم و در آخر تعداد عناصر رو مشخص می‌کنیم:

```rust
let a: [i32; 5] = [1, 2, 3, 4, 5];
```

اینجا `i32` یعنی `type` تمام عناصر `array` هست و `5` یعنی این `array` دقیقا `5` تا عنصر داره.

اگه بخوایم همه‌ی عناصر `array` از اول یه مقدار یکسان داشته باشن، می‌تونیم کوتاه‌ تر بنویسیم:

```rust
let a = [3; 5];
```

یعنی یه `array` با `5` تا عنصر بساز و مقدار همه‌شون رو `3` بذار. در واقع دقیقا معادل اینه:

```rust
let a = [3, 3, 3, 3, 3];
```

فقط روش اول کوتاه‌ تر و تمیزتره. 

بعد این که`array` یه تیکه مشخص و ثابت از `memory` هست که اندازش از قبل معلومه و برای دسترسی به هر عنصر `array` می‌تونیم از `index` استفاده کنیم:

```rust
fn main() {
    let a = [1, 2, 3, 4, 5];

    let first = a[0];
    let second = a[1];
}
```

اینجا `a[0]` یعنی اولین عنصر `array`، پس مقدار `first` میشه `1`. همین‌طور `a[1]` یعنی دومین عنصر، پس مقدار `second` میشه `2`.

حالا بیا ببینیم اگه بخوایم به `index`ـی دسترسی پیدا کنیم که اصلا داخل `array` وجود نداره چه اتفاقی میفته:

```rust
use std::io;

fn main() {
    let a = [1, 2, 3, 4, 5];

    println!("Please enter an array index.");

    let mut index = String::new();

    io::stdin()
        .read_line(&mut index)
        .expect("Failed to read line");

    let index: usize = index
        .trim()
        .parse()
        .expect("Index entered was not a number");

    let element = a[index];

    println!("The value of the element at index {index} is: {element}");
}
```

اینجا برنامه داره از کاربر یه `index`ـی می‌گیره و با `a[index]` مقدار اون `index` رو از `array` برمی‌داره. 

حالا چون `a` فقط `5` تا عنصر داره، `index`های معتبرش فقط `0` تا `4` هستن. پس اگه `0`، `1`، `2`، `3` یا `4` وارد کنی، همه‌چیز درست کار می‌کنه. ولی اگه مثلاً `10` وارد کنی، Rust برنامه رو متوقف می‌کنه و پنیک میکنه:

```text
index out of bounds: the len is 5 but the index is 10
```

فکر کنم خیلی واضحه که چه اتفاقی داره میفته، `array` پنج تا عنصر داره، ولی تو خواستی به عنصر شماره‌ی `10` دسترسی پیدا کنی، که وجود نداره.

این برنامه وقتی به یه `index` نامعتبر میرسه، موقع اجرای `indexing` با یه `runtime error` متوقف میشه و دیگه به `println!` آخر نمی‌رسه. یعنی هر بار که میخوای با `index` به یه عنصر دسترسی پیدا کنی، `Rust` میاد چک می‌کنه که `index` از طول `array` کوچیک‌ تر باشه و اگه `index` بزرگ‌ تر یا مساوی طول `array` باشه، Rust یه `panic` میده و برنامه رو متوقف می‌کنه و این بررسی هم حتما باید موقع `runtime` انجام بشه، چون `compiler` نمی‌تونه از قبل بدونه کاربر موقع اجرای برنامه چه عددی وارد می‌کنه.

این الان دقیقا یکی از مثال‌های `memory safety` در `Rust` هست. توی خیلی از زبان‌های سطح پایین کلا چنین بررسی‌ انجام نمیشه و اگه `index` اشتباهی بدی، ممکنه برنامه به یه قسمت نامعتبر از `memory` دسترسی پیدا کنه که باگ های امنیتی خطرناکی ایجاد میکنه. `Rust` برای جلوگیری از این اتفاق، به جای اینکه اجازه بده برنامه به `memory` نامعتبر دسترسی پیدا کنه، سریع `panic` می‌کنه و برنامه رو متوقف می‌کنه.
