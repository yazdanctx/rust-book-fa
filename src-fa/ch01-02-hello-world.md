طبق معمول، اولین کاری که ما برای یادگیری یه زبان برنامه نویسی انجام میدیم، نوشتن یه کد ساده اس که `Hello World!` رو داخل ترمینال پرینت کنه:

> من فرضو این گرفتم که شما یه آشنایی پایه با کامندلاین داری، و اینکه فرقی نداره که شما از چه کد ادیتوری استفاده میکنی و شما هرجور که عشقت میکشه این کد رو ران کن. من خودم معمولا با `nvim` یا `Zed` کد میزنم، ولی امروزه دیگه تقریبا تمام `IDE` ها از `Rust` پشتیبانی میکنن و مثلا همین `Zed` حتی `LSP` زبان `Rust` رو به صورت پیشفرض نصب داره.

### راه‌اندازی دایرکتری پروژه

برای `Rust` که فرقی نداره شما کدتو داخل کدوم دایرکتری میذاری، ولی بهتره که شما یه دایرکتری مخصوص این کتاب بسازی و همه کدای مرتبط با این کتاب رو، بتپونی اونجا.

الان یه ترمینال باز کن و این کامند هارو وارد کن تا یه پوشه `projects` و داخلش یه پوشه برای پروژه «Hello, world!» ساخته شه.

برای لینوکس، مک و `PowerShell` روی ویندوز، اینو وارد کن:

```console
$ mkdir ~/projects
$ cd ~/projects
$ mkdir hello_world
$ cd hello_world
```

برای `CMD` ویندوز، اینو وارد کن:

```cmd
> mkdir "%USERPROFILE%\projects"
> cd /d "%USERPROFILE%\projects"
> mkdir hello_world
> cd hello_world
```

### مبانی یه برنامه `Rust`

حالا یه فایل سورس جدید بساز و اسمشو بذار `main.rs`.

فایلهای راست همیشه با پسوند `.rs` تموم میشن. اگه توی اسم فایلت بیشتر از یه کلمه استفاده میکنی، قرارداد اینه
که با آندرلاین از هم جداشون کنی. مثلا به جای `helloworld.rs` بنویس `hello_world.rs`.

حالا فایل `main.rs` که تازه ساختی رو باز کن و لیستینگ ۱-۱ رو داخلش بنویس.

<span class="filename">نام فایل: main.rs</span>

```rust
fn main() {
    println!("Hello, world!");
}
```

<span class="caption">لیستینگ ۱-۱: برنامه‌ای که `Hello, world!` رو چاپ می‌کنه</span>

فایل رو سیو کن و برگرد به ترمینالت توی پوشه `~/projects/hello_world`.

روی لینوکس و مک، این کامند هارو وارد کن تا فایل کامپایل و اجرا شه:

```console
$ rustc main.rs
$ ./main
Hello, world!
```

روی ویندوز به جای `./main` دستور `.\main` رو وارد کن:

```powershell
> rustc main.rs
> .\main
Hello, world!
```

حالا سیستم‌ عاملت هر چی که باشه، رشته `Hello, world!` باید توی ترمینالت چاپ شه.

اگه این خروجی رو نمی‌بینی، برگرد به بخش [«رفع مشکل»][troubleshooting] از بخش نصب تا
ببینی چطوری باید ردیفش کنی.

اگه `Hello, world!` چاپ شد، بهت ماشالا میگم!  🎉

### کالبدشکافی یه برنامه راست

بذار این برنامه «Hello, world!» رو با هم بشکافیم ببینیم چجوریاس.

اول که این تیکه کد رو داریم:

```rust
fn main() {

}
```

این چند خط یه تابع به اسم `main` تعریف میکنن، بعد این تابع `main` یه تابع معمولی نیست و توی هر برنامه `executable` که با `Rust` میسازی، اولین کدی که اجرا میشه همین `main` هست و این در واقع نقطه شروع برنامه محسوب میشه

توی خط اول، یه تابع به اسم `main` تعریف شده که هیچ پارامتری نمیگیره و هیچ مقداری هم برنمیگردونه. اگه قرار بود پارامتری داشته باشه، باید داخل پرانتز `()` نوشته میشد.

بدنه تابع هم بین آکولادهای `{}` قرار میگیره.

توی `Rust` ، همه فانکشن ها باید بدنشون داخل `{}` باشه و این اجباریه.

طبق `convention` های رایج کدنویسی هم بهتره آکولاد باز `{` رو همون خطی بنویسی که تابع رو تعریف کردی و فقط قبلش یه اسپیس بندازی.

> من وقتی با یک زبانی کد میزنم، دوست دارم کدم همیشه یه ظاهر استاندارد با بقیه پروژه های مرتبط با اون زبان رو داشته باشه، و داخل `Rust` میشه از ابزار `rustfmt` استفاده کرد که کد رو به صورت خودکار طبق استاندارد های `Rust` فرمت میکنه. بعد این `rustfmt` به صورت خودکار همراه خود `Rust` نصب میشه و به احتمال زیاد همین الان آلردی روی سیستمت نصبه.

### کامپایل و اجرا

تا اینجا اولین برنامه `Rust` خودت رو اجرا کردی، حالا بیا ببینیم پشت صحنه دقیقا چه اتفاقی افتاد.

قبل اینکه اصلا یه برنامه `Rust` اجرا بشه، اول باید کامپایل بشه دیگه، درسته؟

برای این کار هم از کامپایلر `Rust` یعنی `rustc` استفاده میکنیم و اسم فایل سورس رو بهش میدیم:

```console
$ rustc main.rs
```

اگه قبلا با `C` یا `C++` کار کرده باشی احتمالا این دستور برات آشناست چون این تقریبا همون کاریه که `gcc` یا `clang` انجام میدن.

اگه کامپایل بدون خطا انجام بشه، اونوقت `Rust` یه فایل `binary executable` برات میسازه ( میشه همون فایل اجرایی ).

روی لینوکس، مک یا `PowerShell` ویندوز می‌تونی با دستور `ls` فایل‌های داخل پوشه رو ببینی:

```console
$ ls
main  main.rs
```

روی لینوکس و مک معمولا این دو فایل رو می‌بینی:

- `main.rs` → فایل سورس برنامه
- `main` → فایل اجرایی (`executable`)

روی ویندوز، اگه از `CMD` استفاده کنی، خروجی این شکلیه:

```cmd
> dir /B
main.exe
main.pdb
main.rs
```

اینجا سه تا فایل داری:

- `main.rs` → سورس کد برنامه
- `main.exe` → فایل اجرایی
- `main.pdb` → فایل اطلاعات `debug` که موقع دیباگ کردن برنامه به درد می‌خوره.

بعد از اینکه فایل اجرایی ساخته شد، خودت اون رو اجرا می‌کنی:

```console
$ ./main
```

یا روی ویندوز:

```powershell
> .\main
```

اگه داخل `main.rs` همون برنامه‌ی `Hello, world!` رو نوشته باشی، خروجی این می‌شه:

```text
Hello, world!
```

و این متن داخل ترمینال چاپ می‌شه.

حالا شما اگه با زبان هایی مثل جاوا اسکریپت و پایتون کار کرده باشی احتمالا برات عجیبه که چرا اول باید یه برنامه رو کامپایل کنی و بعد اجراش کنی.

دلیلش اینه که `Rust` یه زبان `ahead-of-time compiled` یا همون `AOT` هست.

یعنی قبل از اجرا، کل برنامه به کد ماشین (`machine code`) کامپایل می‌شه.

نتیجه‌ش اینه که یه فایل اجرایی مستقل داری که می‌تونی بدی به هر کسی و اون شخص حتی اگه `Rust` روی سیستمش نصب نباشه، باز هم می‌تونه برنامه رو اجرا کنه.

ولی توی زبان‌هایی مثل پایتون یا جاوا اسکریپت قضیه فرق می‌کنه.

مثلاً اگه فایل `main.py` رو به یکی بدی، اون شخص باید `Python` روی سیستمش نصب باشه تا بتونه اون فایل رو اجرا کنه.

اگه فایل `.js` بدی، باید یه `JavaScript runtime` مثل `Node.js` یا یه مرورگر داشته باشه.

چون این زبان‌ها موقع اجرا، کد رو توسط `runtime` یا `interpreter` اجرا می‌کنن و خبری از یه فایل اجرایی مستقل نیست.

بعد اون مدل هم یه مزیت داره و مثلا توی پایتون یا جاوا اسکریپت معمولا فقط با یه دستور هم برنامه اجرا می‌شه و هم هر آن چیزی که لازم باشه پشت صحنه انجام بشه.

اما `Rust` کامپایل و اجرا رو از هم جدا کرده و خوب این یه `trade-off` خیلی منطقی برای زبان سطح پایینی مثل `Rust` هست، یعنی شما در ازای سرعت اجرا، آپتیمایز بودن و مستقل بودن فایل خروجی، باید یه مرحله کامپایل هم انجام بدی.

مثل هر تصمیم دیگه‌ای توی طراحی زبان‌های برنامه‌نویسی، این هم یه `trade-off` محسوب می‌شه؛ یعنی در ازای سرعت اجرا، بهینه بودن و مستقل بودن فایل خروجی، باید یه مرحله‌ی کامپایل هم انجام بدی.

### برای شروع خوبه، ولی برای پروژه‌های واقعی نه

این `rustc` برای برنامه‌های کوچیک کاملا جوابه ولی هرچی پروژه بزرگ‌تر بشه، مدیریت دپندنسی ها و تنظیمات کامپایل، ورژن ها، تست ها و غیره با `rustc` خیلی سخت میشه.

برای همین `Rust` یه ابزار دیگه ای به اسم `Cargo` داره.

کارگو سیستم مدیریت پروژه و پکیج `Rust` محسوب می‌شه و تقریبا تمام پروژه‌های واقعی `Rust` با اون ساخته میشن.

ازین چپتر به بعد با `Cargo` آشنا می‌شی و می‌بینی چطور کار توسعه‌ی پروژه‌های واقعی `Rust` رو خیلی راحت‌تر می‌کنه.
